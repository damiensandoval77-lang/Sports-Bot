## 3. Branches, PRs and release governance
All 310 branch HEADs were individually compared to main through the GitHub API. The branch report records SHA, open PR association, ahead/behind, merge base, and comparison outcome. **Diverged != unmerged.** Squash merges can leave old branch histories diverged forever.

At audit time, 12 PRs were open. Do not bulk merge or delete 309 diverged branches. First triage open PR conflicts and stale branches by ownership, age, and actual work not yet present on main. Most importantly, configure branch protections so a failing production contract cannot reach main.

## 4. Architecture risk: independent green workflows are not an overall green release
The release, data ingest, model, frozen ledger, live scores, player boxes and settlement branches have independent schedules, approvals and file writers. Success of Pages, a refresh, or mobile rendering does **not** establish complete freeze/grading for the slate. Correctness needs one versioned per-game manifest linking official fixture ID, source quote ID, captured line and timestamp, forecast build ID, live box evidence and immutable settlement decision. Until this exists, health must remain FAIL/WARN at the aggregate level when any critical stage is incomplete.

## 5. Changes not authorized by this audit
This audit **does not** change bets, lines, player statistics, model weights, stored grades, payment/API polling, or the production deployment. It does not claim to have executed every Python test or every branch as a separate deploy. Full-source syntax coverage and individual branch ancestry checks are narrower than exhaustive semantic and runtime testing.

## 6. Closure criteria before telling the owner that the system is fixed
1. Branch checks are enforced as required (prove effective main ruleset, not comments).
2. Nightly standard-quote captures and pretip forecast ledgers reconcile all scheduled games with explicit exceptions before tip, and subsequent grades reconcile every eligible final.
3. Both sports' independent live score and player-stat feeds pass a complete actual game without stale regression.
4. The deployed iPhone-sized browser passes on the release that includes fixes; a real iPhone Safari session is confirmed separately if demanded.
5. Actions fail visibly on provider outages, missing lines, missing frozen picks and overdue grades; no healthy conclusion from null or missing source files.
6. A 72-hour production acceptance window passes with per-game evidence. A unit-test pass alone cannot satisfy this criterion.
